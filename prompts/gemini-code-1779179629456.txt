We are implementing an Admin Dashboard for "EduCrate 2.0"—a note-sharing platform for Computer Science students. The platform currently allows public, unauthenticated users to browse, upload, preview, and download PDF resources. 

### Core Constraint & Architecture Choice:
- DO NOT create a public user registration system. 
- Use "Option 1: Admin-Only Login". Students remain 100% anonymous/public and do not log in to browse or upload.
- Only a pre-seeded Admin user in the MongoDB database can log in to access the Admin Panel.
- Use Role-Based Access Control (RBAC) to secure sensitive mutations (Delete, Pin, Subject Alterations) on the backend.

STEP 1: BACKEND DATA LAYER & AUTHENTICATION
----------------------------------------------------
1. Create `server/models/User.js`:
   - Schema fields: `email` (String, unique, required), `password` (String, required), `role` (String, default: 'admin').
2. Implement `server/middlewares/authMiddleware.js`:
   - Write a `protectAdmin` middleware that extracts a JWT from the `Authorization: Bearer <token>` header.
   - Decode the token, find the user in MongoDB, and verify `user.role === 'admin'`. If invalid or missing, return a 401/403 status code with explicit error messages.
3. Create `server/controllers/authController.js`:
   - Implement `loginAdmin`: Validate email and password against the database using `bcryptjs.compare()`.
   - On success, generate and sign a JWT containing the user ID (expires in 1 day) and return the token along with user info.
4. Update `server/routes/apiRoutes.js`:
   - Register `POST /api/auth/login`.
   - Leave `GET /api/resources` and `POST /api/resources` fully PUBLIC so students can access and upload without tokens.
   - Protect `DELETE /api/resources/:id` and `PATCH /api/resources/:id/pin` using the `protectAdmin` middleware.
